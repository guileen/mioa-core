# render-v1: GOS local rendering service

`graphics_render_v1.h` is the C11 provider/compositor interface. The service, resource ledger, broker transport, scene registry, submission uses and platform backend are implemented in Graphics. The caller serializes calls on the service owner executor; the Graphics Zig client offers bounded asynchronous request cells. A provider never receives a resource endpoint, backing index, pool or native pointer. Three-way latest-state buffering is private policy.

## Admission and identity

The trusted system connects an authenticated provider using a private endpoint-issuance operation. The endpoint binds the provider's real memory account and authenticated executor identity. An untrusted request cannot choose a payer or process. Compositor endpoints are issued separately and may submit views and read hit geometry; provider endpoints own only their registered Surfaces. Negotiate accepts an exact major/minor version and complete struct sizes, rejects unknown required features, and returns actual supported features and capacities. Handles are opaque scope/id/generation triples, never array positions. Endpoint epoch, handle generation, configuration revision, scene revision, focus epoch and device epoch are independent freshness boundaries.

All structures with `struct_size,version` must be initialized exactly; reserved fields are zero. Success outputs are initialized by the service. Rejections leave output bytes unchanged and admit no new writer or scene use. `PENDING` denotes retained in-flight work, not completion. Numeric statuses are the resource-v1 status constants. A successful scene submission is accepted, not necessarily dispatched, GPU-completed or presented.

## Surface and producer

A Surface has one configuration authority and one outstanding writer. Create/configure specify nonzero extent, RGBA8 and monotonically increasing configuration. Configure rejects an active writer; no stale configuration can publish. Multiple independent Surfaces can belong to the same authenticated endpoint/domain and have independent production progress, up to negotiated capacity.

Acquire returns extent, exact native row stride and writable byte span, plus an opaque lease and transfer rendezvous/epoch. The transfer string is not authorization; the broker checks the pinned peer process identity. The writer initializes every image byte required by its pixel format, releases every writable alias and returns its authenticated operation completion. Finish accepts only operation evidence validated by the trusted executor adapter against that exact lease. A provider boolean, timeout or socket EOF is not completion proof. Finish publishes immutable content and settles the writer. Abandon uses the same terminal-proof requirement but publishes nothing. On ambiguity the adapter quarantines the lease, retaining its broker and charge until independently observed matching process termination permits settlement.

A publication is an immutable Surface/configuration/sequence/content identity, not a permanent resource capability. Per Surface the service retains only the current reader R and newest ready M, plus the sole outstanding writer W. A new completed producer result automatically replaces and retires the previous M. An accepted scene replaces R only after every queued/prepared/dispatched/UNKNOWN native use of that exact previous R has settled; platform presentation is not the safety boundary. Displacement automatically closes the old private resource capability, while already-owned scene/native holds obey their own terminal evidence. Closing a public publication releases producer ownership but does **not** make a still-eligible R or M unretainable by another scene. A close for an already displaced identity returns `STALE`: the service has already released that ownership, not leaked it into a historical list. Surface close/revocation retires both roles. Stable-extent operation uses three backing allocations; separately bounded and charged resize/unknown retirement can backpressure rather than allocate unbounded history. Public calls never select buffer count or consumer indexes.
The qualified transfer binding is `MG_RENDER_TRANSFER_AUTHENTICATED_LOCAL_IMAGE`, version 1. A non-Web consumer links the standard transfer implementation and calls `mg_render_transfer_open_v1(target, connection, writer_storage, mapping)` using an authenticated local stream socket and expected host PID/UID supplied by its connection assembler. These credentials pin the real peer process incarnation, not a caller-selected authorization principal. `writer_storage` is caller-owned, initially zero and never copied while open; opening/closing performs no per-target heap allocation. The only provider-visible pointer is ordinary writable byte memory in `mapping.bytes`. The provider initializes the whole authorized span, including row padding, then calls `mg_render_transfer_close_v1` before sending its operation completion. Native allocation tail is not authorized and is never written through this mapping. The current qualified backend is macOS; unknown kinds/versions reject rather than interpreting a private native protocol.

Resource-v1 GPU `DESCRIBE.logical_bytes` remains its frozen value zero. GOS computes the render target span with checked `plane[0].row_stride × height ≤ allocation_bytes`; no existing ABI field changes meaning.


## Composition and input

A scene submission contains the complete intended view set and expected accepted revision. Each view references only a service-issued Surface and immutable content. `mg_render_publication_select_v1` is a compositor-only, non-consuming selection query: it returns newest M if R has no queued or unsettled native use, otherwise exact current R. It returns the original publication identity and sequence, never a private slot/resource/native type. No eligible content for the current Surface configuration returns `NOT_READY`; failed calls leave output unchanged. Selection is a point-in-time observation, not a reservation: producer replacement or another accepted scene can make a candidate stale before submission. Each Surface is independent, so held reader A does not prevent Surface B advancing.

The compositor must retain publication, provider metadata, configuration/extent and any adapter-owned pixel scale as one frozen unit while that publication can remain selected. Pending A must use its exact retained old binding/authority, or omit A if no matching unit exists; it must never put old pixels beneath newer provider authority. A scene may repeat the **same** Surface/publication in distinct views and consumes that Surface once regardless of view order. Distinct publications of the same Surface in one scene return `NOT_READY` rather than admitting two native reader backings. A request to replace a still-held R also returns `NOT_READY`, without blocking unrelated Surfaces. Configuration/publication freshness comparisons apply within a Surface; a View can rebind from Surface A configuration 20 to Surface B configuration 1 with a valid View binding revision.

The service resolves private endpoints/resources and atomically installs the complete binding set only when the backend/scene ledger admits the scene. Unsupported opacity/transform or other admission rejection leaves the last accepted binding usable. Consumption and automatic retirement happen once per Surface after successful admission. No second GPU-use or memory ledger is maintained. Resource holds for queued, submitted and native-completing scenes remain in the existing ledger and broker.

The backend emits distinct accepted/submitted/completed/presented/failed/unknown events. Only actual platform presentation activates a frozen geometry snapshot for hit testing. Late receipts settle the original snapshot; they never reconstruct bindings from current application metadata. Generic adapter_binding is an uninterpreted caller identity; no Web, DOM, document, Profile or origin field is in render-v1. Web authorization and final Core bind acknowledgment remain the Web adapter's responsibility. Focus epochs monotonically advance; inverse-transform/clip/z hit testing rejects invalid matrices and reads the last confirmed presented snapshot. Closing/revoking a Surface immediately removes its hit eligibility even if an old scene remains physically displayed.
Hit results are Surface-local pixel coordinates: inverse-transform the window point, subtract the destination origin, then multiply by the ratio of Surface extent to destination extent. Provider-specific logical units (for example device scale) remain adapter-owned. A configuration change immediately suppresses old presented geometry until a matching configuration is actually presented. The current SDL backend explicitly rejects non-identity transforms and non-opaque views rather than silently rendering different geometry.

Native completion and callback retirement are independent. `COMPLETED` releases the exact native resource holds at the real fence even if platform presentation is delayed or missing; its status distinguishes successful versus failed native termination. It does not prove presentation and does not permit the client to discard callback/frozen geometry state. `PRESENTED` identifies actual platform callback evidence and activates that immutable geometry only. `RETIRED` identifies a successful native-completed scene whose unpresented callback has been explicitly cancelled, making its frozen callback geometry releasable without inventing presentation. `FAILED` is callback-terminal as well: if native failure precedes safe callback retirement, the interim event is `COMPLETED` with failure status, then `FAILED` after retirement. Callback cells remain bounded: full callback capacity or shutdown may retire a native-completed, unpresented cell without requiring a new scene submission, and a later native callback for its retired generation is a no-op. ACK of any `COMPLETED` scene stays `PENDING` until it is presented or retired; the last confirmed presented snapshot remains retained for input. Timeout, CPU exit, callback cancellation and presentation are never substitutes for native fence termination.

The private asynchronous client requires an explicit two-owner destruction handshake: the service owner stops scene admissions after earlier jobs, SDL drains/cancels undispatched scenes and retires callbacks only after native safety, then SDL acknowledges it will no longer enter present/drain before the service owner destroys the Bridge. UNKNOWN work never grants that acknowledgement. Post-join exclusive release keeps the same native-safety rules; there is no global GPU wait or cross-Surface synchronization.

`mg_render_device_event_get_v1` reports the current actual device generation and device-loss state. A trusted backend invalidation stops new target/scene admission and input without inventing writer or GPU termination. Pending uses remain in their original ledgers; recovery requires a fresh service/device incarnation after actual settlement, not resetting a live object.


## Stats and capability limits

The owner reads a bounded `mg_render_stats_v1` snapshot with no per-frame JSON or allocation. Availability bits qualify native backing allocation/reuse/live/highwater, native command counts, memory-account usage and acquire/publish/consume/complete/present sequence endpoints. Counts come from the real backend/ledger, not buffer-selection counts. No RSS, physical-page reclamation, platform GPU duration or hardware-isolation claim is made. A field without its availability bit is unavailable, not a measured zero. Shared-image composition performs no CPU upload/copy/readback; command/byte fields only claim values the backend actually measures. Safe GPU completion and actual presentation remain separate evidence.
`MG_RENDER_STATS_TRANSFER_BYTES` qualifies the zero-byte upload/copy/readback values only for this service's provider-image path when its measured native copy/readback command counts are zero. It does not measure Shell UI texture staging, platform compositor copies or GPU hardware time. `backing_allocations` is the native surface allocation-call counter, including attempts; successful native objects and disposal remain separately tracked by the underlying resource backend.

The service owns a startup-allocated 4096-record trace ring. `mg_render_trace_drain_v1` copies at most caller capacity and destructively drains records without allocating. Overflow or a failed monotonic clock read sets a sticky overflow bit, invalidating complete-trace qualification; records are never silently overwritten. Each record has sequence, `CLOCK_MONOTONIC` nanoseconds, phase, Surface/content identities, request/revision/submission and real native allocation/reuse counts. Acquire, publish and scene acceptance are recorded on the owner; dispatch, observed native fence completion and actual presented callback timestamps are captured on the SDL/backend thread and published atomically for owner draining. Native completion timestamps are CPU observations of a fence, not hardware GPU duration. Each scene phase records each referenced Surface independently; a Surface's publication sequence, not a Web animation callback, defines frame progress.

Private integration behavior fixtures are `mioa-graphics/tests/render_nonweb_provider.c` (public-header-only provider) and `render_service_test.m` (authenticated process, three Surfaces on one domain, actual shared mapping, Metal blit/readback oracle, reuse and GPU-complete-without-present semantics). They are implementation tests and require the native platform qualification; writing these fixtures is not a claim that they were executed.
